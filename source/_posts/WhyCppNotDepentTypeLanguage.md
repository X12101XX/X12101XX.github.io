模板从表面上看，确实是依值的（比如 `std::array<T, length>` 就显然依值），那么，为什么模板类型不算依值类型呢？
<!-- more -->

## 什么是依值类型

在百科上，可以很简单的找到如下的定义
> ：**依值类型**（旧译**依赖类型**，**dependent type**）是指依赖于值的[类型](https://zh.wikipedia.org/wiki/類型系統)

直白来说，也就是依赖值的类型，没有什么好说的



## C++ 的模板真的有在依赖值吗

### 看起来，确实依赖？！

我们先看一段典型的依值类型语言，Lean4 的代码：

```lean4
def arr1: Vector Int 3 := #v[1, 2, 3]
def arr2: Vector Int 4 := #v[1, 2, 3, 4]
```

它看上去和下面的 C++ 代码差不多：

```cpp
std::array<int, 3> arr1{1, 2, 3};
std::array<int, 4> arr2{1, 2, 3, 4};
```

你也可以从类型上知晓它们各自的长度，就好像 `std::array` 真的依赖 `size_t` 类型的长度一样



### 那么，区别呢

我们考虑一个函数，你给定一个值 $n$ ，我们返回长度为 $n$ 的数组（值全为零），并且要求可以在类型层面分辨不同长度的数组。

Lean4 可以很简单的这样做：

```lean4
def zeros : (n : Nat) -> Vector Int n
  | Nat.zero => #v[]
  | Nat.succ s => (zeros s).push 0
```

其中，`Nat` 代表**自然数**。

而让我们想一想 C++ 中要怎么做...好像做不到？！C++ 的模板参数是在编译时确定的，非常量根本无法作为模板参数。

虽然C++ 的模板参数 `N` 也能作为符号参与类型表达式，严格意义上，我们依旧可以用模板传入参数，但是此时传入的参数已经和函数没什么关系了，比如如下的函数：

```cpp
template <std::size_t N>
constexpr std::array<int, N> zeros() {
    return {};
}
```



### 编译期常量真的是问题所在吗

让我们进一步思考，Lean4 和 C++ 中，我们传入 $n$ 的方式不同在哪里：

- Lean4 中，$n$ 就是一个再正常不过的参数
- C++ 中，$n$ 实际上是一个模板参数

在 Lean4 中，其传入的 $n$ 可以在运行时才确定。而且对于 `zeros` 函数，其返回类型可以根据参数而发生变化，让我们仔细看 `zeros` 的实现：

- 当 $n$ 是 0 时，我们返回 `#v[]`，也就是一个空数组

- 当 $n$ 是一个 $s$ 的后继时，我们返回 `(zeros s).push 0` ，这是一个递归过程

  不难看出，对于 $n$ ，这个函数会运行 $n + 1$ 次，也就会添加 $n$ 个 0 到空数组中.

他们真正的区别是：**值在类型中出现的位置**

C++ 只允许可以在编译期确定的值出现在模板参数里，而Lean4没有这种限制，即使是一个运行时才可以确定的值，也可以作为类型的一部分。



不过，这并不代表 Lean4 可以随便写类型参数，比如这样一段代码：

```lean4
def wrong (n : Nat) : Vector Int n :=
  #v[1, 2, 3]
```

它就不能编译，因为我们显然无法保证所有的 $n$ 都有 $n = 3$，而先前的代码则可以在类型上证明一定会有类型上给出的关系，具体为什么再次不做赘述。
